# Q-Sample 第三版：NLQTSBench 数据与方法适配审计

日期：2026-11-04，北京时间。本版仅做官方元数据、已有 CSV、少量新增训练 CSV 和评分代码的 CPU 审计。没有训练、GPU 实验、LLM/API 推理、修改官方题目或使用测试标签训练。第一版、第二版报告分别归档在 [v1/REPORT.md](../v1/REPORT.md)、[v2/REPORT.md](../v2/REPORT.md)，原名为 `REPORT_V1.md`、`REPORT_PHASE2.md`。

## 审计判断

**可以转向官方 NLQTSBench 开展数据与机制验证，但目前不能批准“任务已经适合证明 Query-Adaptive Compression”的结论，也不应直接进入主模型训练。**

| 核心问题 | 当前证据与判断 |
|---|---|
| A. 是否真正需要 Query 条件证据选择？ | 同 CSV 的多 Query 确实存在，且答案不同；但 Shape 没有这种直接配对，其他两类每组答案端点很少，尚未证明 32/64 Tokens 下 Query Blind 无法保留全部必要证据。未完成可靠的波形 Oracle / 共享答案头比较。 |
| B. 空间 GT 是否合法、有效且无明显捷径？ | 训练集提供合法的答案区间/时间点，可作为显式定位监督；**没有完整 Evidence Span 标签，也没有唯一正确的 Density GT**。位置监督本身会让坐标携带答案，必须独立评估其信息通道，不能称为天然防捷径。 |
| C. 无 LLM 能否建立强且不旁路的轻量答案头？ | 三类都是结构化时间输出，原则上不需要自由文本 LLM；但现有二分类头不适用。可设计数值验证器或指针头，**尚未验证其在稀疏不规则采样下足够强，也未排除坐标替代波形的路径**。 |

先推进 CPU 的输入范围、证据充分性、配对 Oracle 和答案头验证。三个条件未满足前，不以辅助 Loss 收敛或最终 IoU 提高宣布 Q-Sample 核心假设成立。

## 1. 从第一、二版继承的事实

第一版 Signal-Only 的 Adaptive 平均准确率 97.66%，Uniform 为 60.94%；No Blur 为 61.20%。但 Query Blind 平均仍有 75.91%，Query 切换未稳定把采样转到所问目标。`signal_time` 出现过采样值全部置零仍 100% 准确率的明确反例。

第二版 91 项运行没有验证条件化选证据：32/64 Tokens 的 Adaptive 训练 BCE 也接近 0.693，说明不能只归咎于测试分布。512 Tokens 强干扰下 Adaptive 58.46%，公平平滑 Uniform 76.17%。粗特征直接分类能接近 100%，经采样链路仍失败；查询盲窗口 Oracle 在 32 Tokens 达 94.53%。

因此要分开处理：局部统计是否丢形态、QA 坐标梯度是否到达事件、逆 CDF 梯度是否稳定、答案头能否解码变形形态，以及任务是否真的需要按 Query 分配容量。实际信号插值在平坦区没有坐标梯度；高斯平滑只在有限邻域扩展梯度，还会抹掉高频事件；更细粗网格和小密度下限不能单独解决这些问题。**真实 Benchmark 不会自动修复上述优化机制。**

## 4. 三类候选任务的标签语义

| 任务 | 官方输入意图 | Answer GT 实查 | Evidence 需求与缺口 | 可用空间监督 |
|---|---|---|---|---|
| Shape Identification | 指定通道、搜索窗口、形态及 largest/deepest/longest 等条件，输出目标形态区间 | train 14/14、v2 45/45、test 129/129 是两个完整时间戳；均为正时长 | 形态边缘和前后基线可能在答案外；“最大/最深/最长”还需比较其他候选。没有全部候选及完整证据区域标签 | 答案区间可监督定位；不能作为唯一正确密度。可研究区间+边界/背景的代理分布 |
| Temporal Localization | 指定通道、范围和 maximum/minimum/first above/last below 等条件 | 31/45/72 题全部是**单时间戳字符串**，不是区间 | 极值需比较搜索范围；first/last 阈值事件需前后点和排除更早/更晚候选；精确点不包含这些证据 | 单点或邻域软目标是位置监督代理，邻域宽度是研究者假设，不是官方 Evidence Span |
| Interval Discovery | 指定通道、时间范围和阈值，寻找最长持续 above 区间 | 33/45/72 题全部是双端完整时间戳；均为正时长 | 需要区间内连续性、外侧阈值交叉及其他候选长度；仅密采已知答案内部无法证明它最长 | 可用区间/端点定位监督；缺少所有候选及否定证据标注 |

例如 train `L1_T3_Interval_Discovery_00343` 的答案是 2022-02-20 04:30 至 02-24 13:30，而问题给出的搜索结束只有日期 02-24。v1 meta 保存了 13:30 的精确范围，但它不是自然语言输入的一部分；v2 没有这个字段。**不能读取隐藏 meta 补全推理输入，也不能看 GT 反推搜索端点。** 本审计将日期范围按整天统计有效长度，并将其标为 `date_ambiguous`；正式实验必须预先固定文本日期解释，单独报告与官方隐含精度的差异。

v2 Temporal Localization 有 29/45 题、Interval Discovery 有 31/45 题属于这种日期粒度范围；Shape 的搜索窗口全部给到秒。后续任何 endpoint IoU 差异都应先排除输入语义与时间精度不一致。

**Answer Span、Evidence Span、Density Supervision 三者的关系：** Answer Span 是待输出的位置；Evidence Span 是足以判断形态、边界、极值、次序或关系的观测集合，可能含多个不连续区间；Density Supervision 是训练者选择的预算分配目标。官方没有在这三个任务中发布完整、充分、最小的 Evidence Span 集合，更没有发布密度标签。答案区间只能构造明确标注为“答案位置代理”的辅助目标。

多变量异常尤其不能只监督下游答案区间内的一个通道。旧 v008/v009/v016 审计显示既有单通道捷径，也有读取双通道后仍因程序错误失败的情况。要验证多变量证据，需要同时保留相关通道、背景与关系，不按任务名称自动认定互补性。

## 6. 泄漏审计：ID、问题、原始信号与背景

| 两个发布集 | 相同 ID | 完全相同问题对 | 完全相同 CSV 对 | 左/右侧涉及不同任务数 |
|---|---:|---:|---:|---:|
| train / test | 0 | 7 | 541 | 127 / 247 |
| train-v2 / test | 0 | 0 | 873 | 180 / 258 |
| train / train-v2 | 0 | 2 | 380 | 122 / 165 |

CSV 对数通过**完整文件 Git blob 指纹**计算，覆盖全部发布 CSV，不只抽查文件。它不是独立样本数；同一信号能对应多题，导致多对多计数。逐行核验的已有文件也通过该指纹匹配，未将转换或修改后的 CSV 混入官方数据。

train 与 test 的相同问题中，Interval Discovery `00351` / `00409` 连答案也相同；其他相同问题包括六个异常/报告案例，答案并不全同。问题文本不重叠也不能排除模板重叠：三个发布集共享同一任务语法，只替换通道、阈值、日期、形态等参数。本报告不把数字替换后的模板数当作语义独立问题数。

**不同 CSV 也可能共享背景。** 实际时间对齐比较了 27 个本地训练/测试同名通道配对。例如 train Interval `00343` 与 test Insight `00057` 在 35,040 个公共时间点中有 32,064 个值一致（91.51%）；train Interval `00347` 与 test Global `00009` 的 175,296 点完全相同。这证明仅剔除相同文件仍不足以实现未见原始时序的评估。其余未取得 CSV 的近重复、上游原始文件映射尚未完整核验。

旧 metadata 审计记录 test 的来源分布为 causal_rivers 1,015、ettm1 127、smd_machine_1_1 11。官方 Benchmark 使用真实背景，也包含人工注入形态/异常；“转向真实 Benchmark”不等于全部波形和标签都是无注入的自然观测。本轮保持官方数据原样，不再设计额外 Synthetic QA。

训练共享信号上的新问题可以构成**明确披露的查询泛化**评估；如果样本、问题或答案重复则风险更高。它不能支持“未见源时序泛化”。按保守的同名通道及相同 blob 排除所有官方测试相关输入后，train 三类只剩 2 个 Interval 任务，v2 三类为 0。通道名相同不是普遍的同源证明，但这里这一保守筛选已经说明：不能宣称现有官方拆分天然满足严格源隔离。

### 已接触测试样本

完整测试题目/标签元数据此前已有审计，现在也用于本轮结构核验；并非完全未见。历史已存在的 231 个官方测试 CSV 全部保守标记为 **已接触开发资产**，清单保存在 `audit_results.json → test_exposure`。这不声称每个文件都跑过模型，但不再将其当作新鲜独立测试样本。剩余 922 题仅表示本轮未找到其独立 CSV，不代表问题、标签、公开分数或同源背景完全未被接触。

## 7. 同信号配对与 Oracle 的真实边界

以“CSV 完全一致”定义同一输入，而不是仅依据通道名。筛选三个候选任务后：

| 发布集 | 有多 Query 的同 CSV 组 | 涉及题数 | 每组最大 Query 数 | 每组最多不同答案端点 | Shape 配对组 |
|---|---:|---:|---:|---:|---:|
| train | 18 | 43 | 4 | 6 | 0 |
| train-v2 | 27 | 79 | 5 | 7 | 0 |
| test | 43 | 130 | 5 | 8 | 0 |

每组都至少有两个不同答案。因此可以直接复用官方问题做同信号多 Query 测试，但这些是 Temporal/Interval 的配对，常同时改变阈值、动作和搜索月份，**不是已控制搜索范围、只切换形态意图的配对**。Shape 的不同任务往往是不同局部信号；不能对同一文件随意换一句形态 Query，再自行假定答案。

已经做了一个严格限定含义的 **答案坐标 Oracle 可容纳性诊断**：Query-Aware 只需保留当前答案的 1–2 个时间端点；Query-Blind 保留整组所有答案的端点。32/64/512 Tokens 对上述所有组均能容纳所有端点，坐标支持覆盖上限都是 100%。它使用 GT，不能部署、不能训练主模型；没有读取充分波形，**没有报告 Oracle QA 分数，也不是 Evidence Oracle**。这个诊断只排除了“这些组仅因答案位置数量太多，32 Tokens 就必然需要 Query 选择”的论证。

尚缺的关键比较是：在固定原始输入和相同物理采样预算下，用同一个足够强的回答器比较 Query-Aware **证据** Oracle 与 Query-Blind **证据** Oracle。前者要保留背景、候选和边界；后者须允许聪明地共享这些证据，不能故意均摊所有无关点使其变弱。正式比较应报告原始信号复核的任务分数，而不是只报答案命中率。由于官方缺完整证据标注、现有稀疏读出器尚未校准，本轮不虚构该比较的成绩。

只有在公开开发数据上证实存在稳定的条件选择收益，才值得冻结相应主实验；如果 Query-Blind Oracle 同样很好，应报告“此预算下没有建立条件选择必要性”，不再人为造题或调整测试集。

## 8. 密度辅助监督：可以研究，但不能跳过捷径审计

答案位置监督能给密度 logits 提供绕开插值坐标链的梯度：

\[
L_{dens}=\operatorname{KL}(q_{proxy}\Vert p_\theta(\cdot\mid X,Q)).
\]

这可检验 Phase 2 的优化瓶颈，但 `q_proxy` 必须明确称为训练答案位置的**代理分布**。区间均匀质量、端点邻域、前后背景和全局探索质量的混合是待比较的建模选择，不是官方 Evidence GT；单点标签上的 Gaussian 宽度也不是天然正确的证据范围。跨多个候选的比较或“最早/最后”的否定证据，不能从最终答案自动恢复。

在有合法训练位置标注、且前述输入/读出器检查通过后，才设计以下三个**独立训练条件**，匹配数据、更新次数、初始化、预算、采样后端和至少三种子：

1. **QA Loss Only**：仅原任务的时间点/区间答案损失，保留纯 QA 假设的直接检验。
2. **Density Warm-up → QA Fine-tuning**：前段仅用训练集代理空间目标，后段撤掉空间 Loss，只用 QA；报告撤掉后的密度与证据质量是否保持。QA Only 对照补齐相同总更新次数。
3. **QA + Density Auxiliary**：同时训练，λ 在开发集预先确定，单独报告，不冒充纯 QA 成功。

另设**直接位置回归/起止指针基线**，读取与密度模型相同的粗特征和文本，但直接预测时间。它不是采样法，而是判断“学会定位”是否足以解释全部增益的诊断。密度拟合成功、位置回归成功与完整证据采样成功是三个目标。

### 密度监督为什么可能制造坐标答案通道

假设代理密度在答案区间 `[a,b]` 内均匀，区间外质量极小，则逆 CDF 生成的点近似为 `a+(j+1/2)(b-a)/N`。只看第一个和最后一个坐标就能反推出区间边界，**完全不需要信号值**。这是一条可计算的信息路径，不是本轮已经训练出新捷径的实测成绩。Gaussian 端点目标同样会把位置写入网格；`grid.detach()` 只阻断梯度，不删除前向信息。

因此必须在每个训练条件中分别评估正常输入、Coordinate-Only、Zero-Signal、打乱/替换采样值、同 Query 换为其他真实信号、固定网格重新训练，以及均匀网格 OOD 干预。训练一个匹配分布的 Coordinate-Only 对照，比只在正常模型中推理置零更有解释力。保留 query-only、范围中点/固定跨度先验基线。置零/换网格性能下降本身不能证明因果性；反之，置零仍高分必须披露，不能将定位成绩解释成波形保留。

## 9. 现有模型所需的最小适配与轻量答案头

这一节是有条件的设计，不是已实现模型，也不是开训承诺。优先复用 v2 的逆 CDF、线性采样与数值检查；v1/v2 保持独立不改实验算法。

### 多变量输入与自然语言

底层 `sample_linear` 已支持 `[B,L,C]`，QSample 构造器也支持 channels。v2 `EvidenceReadout` 仍硬编码单通道，四维 One-Hot Query 与 BCE，需要替换。真实适配需变长 mask、缺失值及观测 mask、按训练数据确定的尺度处理、通道 schema 编码，以及每个输出 Token 的通道数/数值字节统计。通道置换应同步 schema，不能按任意通道位置记答案；若时间异步，不能直接套用行索引插值。

可先采用冻结的小文本编码器，例如 [all-MiniLM-L6-v2 官方模型卡](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)提供的 384 维向量，经可训练 Linear/MLP 投影到密度网络宽度，再通过现有 FiLM 的 scale/shift 与粗特征交互。需要精确数字/时间的任务同时保留从原 Query 解析的阈值、通道和时间范围；不能期待句向量无损保存长数字。解析规则在训练开发集固定，失败显式记录，不用 GT/meta 兜底。保留完整原句和原始答案；本轮未下载或运行该编码器，未来须固定权重 revision、tokenizer 和截断策略。

粗统计继续有形态损失风险。先用同样输入做粗特征定位探针，与原始波形数值基线比较；若粗特征本身不能区分目标，再考虑多尺度局部卷积。不能直接加大模型后把采样优化和表征问题混在一起。

### 时间输入的可识别性

| Readout 输入 | 能回答什么 / 缺什么 | 捷径检查 |
|---|---|---|
| Signal Only | 可研究局部形态保留；平移后信号相同，不能唯一恢复官方绝对时间戳；非均匀序列上的普通卷积还混淆物理持续时间 | 是机制控制，不是公平完整定位系统 |
| Signal + Δt | 有物理单位的间隔帮助恢复持续时间；没有起点锚点仍不能确定绝对时间；若给锚点则累计间隔可重建全部坐标 | Δt 的大小和布局仍可编码答案，不等于防泄漏 |
| Signal + Absolute Time | 加绝对锚点、相对秒数/归一化位置可输出官方时间；需同时保留真实跨度，避免不同长短序列混淆 | 必须做零值和坐标对照；时间本来必要，但不能取代所问波形证据 |

不使用浮点 epoch 秒直接做低精度回归；用每条记录的原始时间戳表、相对秒数和时间原点。对于本轮 15 分钟规则网格，浮点采样坐标映射回真实时间后，在输出阶段按固定规则投影到观测时间戳；训练的连续损失和最终离散 exact-hit 是不同东西。遇到不规则或缺失采样需改用时间戳上的 `searchsorted`/插值，不能把 `[0,1]` 行位置误称为物理时间。

### 优先做答案头能力审查

对于 Temporal/Interval，优先使用**无训练的数值验证器**作为读出器审计：从完整原始训练/开发信号和公开 Query 计算极值、阈值过界和最长连续区间；然后只给同预算采样值和时间，检查会损失什么。完整信号结果先与官方 GT 对齐，避免把不一致全部归因于压缩。稀疏点之间不能默认没有未见的极值/过界，跨大间隙的连续性必须标为不确定。固定算法使用同一份 Query 解析，不读 label、density、encoder 特征。它是强诊断候选，尚未在所有稀疏输入上验证足够强。

可训练候选是小型 1–2 层序列/交叉注意力读出器，只接收 sampled values、mask、Query 及所选时间输入；输出单位置或有序 start/end 指针及局部连续偏移。绝对时间只用于把选中位置映射回时间字符串，另设允许时间参与打分的对照。需预先校准其对冻结网格的能力，避免答案头从头学习失败掩盖采样质量。

**但这样的接口也不能理论保证防旁路。** 当密度已经用答案区间训练时，所有可选指针都在答案附近，即便指针分数只依赖值，最终时间仍可能由网格给出。因此推荐的停止条件是：如果匹配分布的 Coordinate-Only 或坐标先验接近正常分数，先将结果定性为“监督定位”，不再声称实现了依赖真实信号的压缩 QA；必要时改用冻结验证器/独立证据充分性指标，仍无法分离就报告任务不适合当前机制论证。

Shape 没有可靠通用数值真值定义：官方参考技能使用形态特定的 rolling/median/极值算法，但它是近似解题程序，不是公开数据生成和标签程序。先对固定训练样本校准参考算法与标签，再决定轻量指针头是否值得训练。不能换成预测六种形态类别作为主任务，因为原任务要求输出时间范围。

| 原始答案类型 | 无 LLM 的输出方式 | 可微训练目标（非官方指标的替代声明） |
|---|---|---|
| 单时间戳 | 时间指针/归一化位置与局部偏移，按观测网格序列化 | 位置交叉熵、Huber；最终仍报官方 exact hit 与补充绝对误差 |
| 时间区间 | 有序起止指针、受约束连续坐标 | 起止 CE/Huber + 连续区间 IoU surrogate；最终报官方时间 IoU |
| 数值/周期 | 小回归头，原始尺度还原 | Huber/相对误差，最终 rel_acc；本轮不是主任务 |
| 日期列表 | 候选日评分与有限集合输出 | 多标签/排序损失；官方 set_f1 会忽略排序，必须披露 |
| 结构化自然语言 | 阶段边界+六种趋势短语+异常时间的结构化头，固定语法渲染 | 边界/类别/异常子损失；保留原报告和官方 report 评分，暂缓首轮 |

这些结构化渲染可以匹配官方答案格式，不需要把任务转换成 Yes/No。定位损失与 Density Loss 可能使用同一份位置标签，所以二者收敛的关联不是独立机制证据。

## 10. 公平对照必须拆成两条评估线

| 方法 | 同预算采样质量线 | 完整 QA 系统线 |
|---|---|---|
| Adaptive | 固定 N、相同 C、时间输入与共享读出器；分别报告三种监督条件 | 各自训练后也可报原任务分数，明确含答案头差异 |
| Query Blind | 仅密度分支不读 Query；答案头仍读 Query | 网络容量、监督/更新与适用的平滑策略匹配 |
| Uniform | 相同输入范围、原始采样预算；保留同样训练平滑与 no-blur 条件 | 不用故意较弱头放大 Adaptive 优势 |
| 局部统计采样 | Query Blind 的极值/方差/差分密度；可另列 Query-aware 数值规则，防止把传统方法都做成盲显著性 | 计入全序列统计扫描成本；参数只在训练开发集确定 |
| Sonar-TS 官方框架 | 原方法不承诺 N 点预算，**不能直接塞进同预算表**。如实现候选点配额限制，应命名 Budget-Capped Sonar，另行记录截断/回退规则和质量代价 | 固定代码/技能版本、模型和调用预算后，作为 SQL+Python 完整系统另表比较官方分数 |

Sonar-TS 使用全局多尺度索引与原始候选数值验证，可能回退读取完整范围；Q-Sample 的密度 Encoder 也扫描完整输入。双方都要核算全序列预处理、索引/Encoder 时延、存储，以及下游真正接触的原始数值数。只比较 32 个输出向量与 Sonar 的 LLM 文本 Token 数不公平。旧 v016 的 Qwen 8B 替代模型运行是部署诊断，不是原版官方模型成绩；本轮不调用 Sonar 线上模型、不搬用旧 10 题混合均分作为本任务基线。[官方系统说明](https://github.com/Atlamtiz/Sonar-TS/tree/99866c43cd7ceb91a929de745e9f49cea92962e5)。

采样质量线报告：答案区命中/占比明确标成 Answer-Span Coverage；有独立证据定义才报 Evidence Coverage。另报边界/背景覆盖、可辨形态/连续性、配对 Query 切换对“本目标减另一目标”的方向性差值、完整任务分数。最终质量应与这些指标同时改善；只把网格画得不同不算成功。

## 11. 划分建议与样本量

**兼容性协议**可以沿用 v2 general 官方 train/valid：三类训练分别为 Shape 31、Temporal 32、Interval 27，合计 90；valid 分别 14/13/18，合计 45。原 train 的 78 个候选任务先作为独立补充开发来源，不默认并入训练；其 Shape 缺 step_up 样本，且多数底层信号与测试共享。全部训练量很小，不能把重复 epoch 或同 CSV 不同 Query 当作新增独立信号。

**更适合机制研究的内部协议**：只从 v2 的 135 个官方候选任务按通道连通组拆分，保留原题不改写，作为单独明确命名的 source-group protocol。已输出一个不看分数的种子 `20261104` 建议清单：按通道名 SHA256 排序后约 70/15/15 分组，得到 train 99 / valid 18 / holdout 18，分别覆盖 33/7/8 个通道。具体任务分布为：

| 内部建议划分 | Shape | Temporal | Interval |
|---|---:|---:|---:|
| train | 38 | 34 | 27 |
| valid | 4 | 7 | 7 |
| holdout | 3 | 4 | 11 |

**这只是可复核建议，不是已经通过的严格源隔离划分。** v2 缺 meta，通道名并不充分识别上游原始文件；仍需用文件指纹、时间/数值近重复、跨变量上游来源建立连通分组，必要时整组合并后重新冻结，并说明小样本/任务不均衡。不能为凑齐某个好分数反复选种子。如果合并后无法得到足够独立组，应停止并报告数据不足。

官方 test 的 273 个三类任务留作外部官方评分，单列信号共享、精确问题重复、既有 CSV 接触和未找到独立 CSV 等标记；不参与调参。对于“未见源时序”主张，不能用这份同源外部测试替代内部源分组 holdout。此次审计检查过标签结构，任何后续结果还应披露开发者已接触这些元数据，不能称作完全未见盲测。

## 12. 第一轮最小验证设计与推进条件

**本次已完成的最小工作**是：官方三个版本的全量元数据核对、全库精确 CSV 指纹重叠、243 个已有/固定补齐文件的内容检查、同输入配对统计和答案坐标 Oracle 容纳性诊断。下面各项仍是建议，尚未运行模型或训练。

1. **输入与答案校准，CPU**：对固定训练/开发样本，核验自然语言窗口精度、通道、真实时间映射；运行完整原始信号数值基线，检查与官方 GT 的一致性。Shape 先做原始局部窗口读出器校准，Temporal/Interval 先查日期端点及稀疏间隙。若全信号也对不上标签，应先报告语义/标注缺口。
2. **同信号配对与预算审查，CPU**：使用官方已有多 Query 组，分别统计 Query 限定范围相同/不同的组。固定 N=32/64/512，同时在原生短序列披露 N≥L 的情况；无需重复插值造长序列。构建能够保持上下文/边界和候选比较的两种证据 Oracle，用同一冻结读出器比较，并做固定网格数值基线。如果未发现条件收益，A 仍未验证，停止扩大训练。
3. **读出器机制审查**：先冻结采样方式，仅校准轻量头；同时训练 Coordinate-Only、Query-Only，并做 Zero-Signal 和跨信号置换。不能只看 OOD 置零下降。若答案几乎可从坐标读出，C 未解决，暂不训练端到端系统。
4. **仅在前项通过后，另行冻结小规模训练**：三种独立 Loss 条件 × Adaptive/Query Blind，配 Uniform、公平平滑、局部统计与直接位置回归。三种子，共享源分组及原任务输出。固定总更新预算、λ 候选、选模依据、失败记录与停止条件；辅助监督只在训练子集构造。

首轮任务优先级是：**Interval Discovery 的原始数值/证据校准 → Temporal 的精确时间与 first/last 检查 → Shape 的局部读出器校准**。这不是把 Interval 指定为已经成立的主 Benchmark：它有清晰区间答案和可复核阈值语义，适合先暴露连续性与坐标捷径；但其最长区间需要域外比较。Shape 更贴近形态语义，却原生序列短、训练少、缺同输入多 Query 配对，因此暂不作为 Query 条件选证据已成立的首个论据。

**进入训练前仍需回答的三个缺口：** 在真实证据层面是否有 Query-aware Oracle 的稳定预算优势；训练答案位置代理能否改善波形充分性而非仅提高定位；轻量头在时间必需且允许读取时，是否仍依赖采样信号。这三项任何一项不成立，都应该报告失败，而不是借更多辅助监督或更大后端掩盖。
