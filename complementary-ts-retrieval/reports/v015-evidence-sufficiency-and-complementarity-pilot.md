# 方向 3 · v015：模型知道什么时候证据已经够了吗？

实验日期：2026-10-30（北京时间）。本轮新建一个受控诊断任务，先在 CPU 上证明证据是否足够，再运行小规模 GPU Pilot。没有训练、下载模型或修改发布数据、旧结果和 README。

**结论先说：我们能构造出真正需要 A 与 B 联合证据的时序 QA 小任务；但本轮尚不支持为“动态互补检索”开发新模型。** 原因是一个固定数值规则已经把全部完整证据题做对，而现有模型的错误在“证据够不够”和“精确比较两个时间”两步都会发生，甚至在直接给出两个事件时刻后仍会出错。

## 1. 题目到底是什么？为什么单看一条序列真的不够？

每题有两条时序 A、B。题目问：**B 的短暂上升脉冲，是否恰好在 A 的脉冲开始后两个采样点（30 分钟）发生？**

模型不是只回答 YES 或 NO，还必须回答当前材料是否足够：

```json
{"sufficient":"YES|NO","answer":"YES|NO|UNKNOWN","missing":"A|B|NONE"}
```

例如一个反事实小方阵中，A、B 的脉冲时刻如下：

| A 开始 | B 开始 | 正确答案 |
|---|---|---|
| 01:45 | 02:15 | YES（相隔 30 分钟） |
| 01:45 | 06:45 | NO |
| 06:15 | 02:15 | NO |
| 06:15 | 06:45 | YES（相隔 30 分钟） |

这里有两个关键配对：固定 A=01:45，只把 B 从 02:15 改为 06:45，答案由 YES 变 NO；固定 B=02:15，只把 A 从 01:45 改为 06:15，答案同样翻转。

所以只给 A=01:45 时，存在一个真实世界答案为 YES，也存在另一个真实世界答案为 NO；显示给模型的 A 数字逐字相同。只给 B 时同理。它不是“模型没答出来，所以猜测证据不够”，而是同一份显示在逻辑上无法唯一决定答案。

每条序列有小幅背景波动和一个清晰的四点上升脉冲。A、B 使用不同数值尺度，事件时刻位于同一 15 分钟日历网格。每个证据窗口有 12 个连续原始数值，没有使用均值、标签文本、题号或条件名。

## 2. 先审计任务，而不是先看模型

构造了 16 个独立的反事实方阵，每个方阵有 4 个 A/B 组合，共 64 个完整世界。每个世界给出六种材料：

| 给模型的材料 | 正确的“证据足够吗” |
|---|---|
| 只给 A | NO，缺 B |
| 只给 B | NO，缺 A |
| A+B | YES，回答 YES 或 NO |
| A+无关 C | NO，缺 B |
| A+A 的重复副本 | NO，缺 B |
| A+B 的错误时段 | NO，缺 B 的脉冲时段 |

CPU 审计结果如下。

| 检查 | 结果 | 说明 |
|---|---:|---|
| 完整 A+B 的固定数值规则 | 64/64 正确 | 阈值找出 A、B 脉冲起点，再检查是否相差两步 |
| 只 A 的不同显示内容 | 32 份 | 每一份均出现在一个 YES 与一个 NO 世界 |
| 只 B 的不同显示内容 | 32 份 | 每一份均出现在一个 YES 与一个 NO 世界 |
| A+无关、A+重复、A+错误时段 B | 每类各 32 份 | 每一份均出现在一个 YES 与一个 NO 世界 |
| YES 与 NO 的 A 起点分布 | 完全相同 | 不能只凭 A 的时间猜标签 |
| YES 与 NO 的 B 起点分布 | 完全相同 | 不能只凭 B 的时间猜标签 |

这个“固定数值规则”是重要的简单对照：它证明完整材料确实足够，也说明这个合成题本身**不需要学习模型才能求解**。它不是通用时序算法，更不是未来论文方法。

## 3. 小规模模型试跑

GPU Pilot 预先固定抽取 4 个完整反事实方阵：16 个世界 × 6 种材料 × 2 个已有模型（ChatTS-8B、Qwen3-8B），共 192 次 greedy 推理。所有输出都保存为原文。

为避免“80 个不足样本、16 个充足样本”让“永远说不足”看上去很高分，主指标使用两类各占一半权重的 **Sufficiency Accuracy（宏平均）**：

- `False Sufficiency Rate`：明明不足却说足够的比例；
- `Full-evidence Answer Accuracy`：在 A+B 足够时，YES/NO 是否正确；
- `Counterfactual flip`：固定 A 改 B，或固定 B 改 A 时，模型是否随正确答案翻转。

| 模型 | False Sufficiency Rate | Sufficiency Accuracy（宏平均） | A+B Answer Accuracy | 16 个反事实翻转全部正确 |
|---|---:|---:|---:|---:|
| ChatTS-8B | 80/80 = 100% | 50% | 8/16 = 50% | 0/16 |
| Qwen3-8B | 0/80 = 0% | 50% | 0/16 = 0% | 0/16 |

这两种失败方向相反。

ChatTS 在 96 次中都输出同一结构：`sufficient=YES, answer=YES, missing=NONE`。因此它不仅没有拒绝单证据、冗余证据和错误时段证据，也没有在 YES/NO 反事实之间翻转。它在本任务上的 50% A+B 分数只是因为完整世界恰好一半为 YES，**不能解释为会使用了联合证据**。

Qwen3 对只 A、只 B、A+无关、A+重复四类材料均能正确说“不足”；对 A+错误时段 B 仍说不足，但错误地报告“缺 A”而不是“缺 B”。更重要的是，它对全部 16 个真正完整的 A+B 输入也说“不足”，答案全部为 UNKNOWN。它不是简单地“总是自信”，而是把已经齐全的原始数值材料误判为不够。

## 4. 这到底是数值理解错，还是充分性判断错？

为拆开这两件事，追加两个小控制，均不加入任何关系标签。

第一组把同样的 16 个 A+B 原始窗口保留，同时附上由 CPU 固定阈值从这些数值中算出的两条脉冲开始时刻。这样模型无需先找脉冲，只需判断两个已知时刻的关系。

| 控制 | ChatTS-8B | Qwen3-8B |
|---|---:|---:|
| 原始 A+B | 8/16 | 0/16 |
| 原始 A+B + 数值规则给出的事件时刻 | 8/16 | 8/16 |

两者在附上时刻后仍把所有负例答成 YES。对 Qwen3 而言，这说明原始数值的脉冲阅读确实是一个障碍，但即便起点已经写出，精确滞后关系仍没有稳定完成。

第二组只给 Qwen3 两个已知时刻，不给任何时序数值，也明确说明证据充分。结果为 **12/16**。它把“B 比 A 早”的 4 个负例答为 NO，却把“B 在 A 之后、但相差远大于 30 分钟”的 4 个负例仍答为 YES。也就是说，它部分使用了先后顺序，却没有稳定检查“恰好两个采样点”这个精确条件。

因此本轮的错误可分为：

| 环节 | ChatTS-8B | Qwen3-8B | 本轮能作的判断 |
|---|---|---|---|
| 判断材料是否足够 | 明显过度自信 | 原始数值 A+B 时过度保守 | 两种模型均不稳定 |
| 从原始数值找出两个脉冲 | 不能由本轮单独量化 | 补充事件时刻后从 0/16 到 8/16 | 对 Qwen3 是一部分原因 |
| 精确比较“相隔两个点” | 事件时刻给出后仍只答 YES | 纯文本时刻也错 4/8 个负例 | 不是单纯检索问题 |
| 反事实一致性 | 0/16 | 0/16 | 两者都未随决定性变量翻转 |

## 5. 研究价值：本轮支持什么，不支持什么？

**支持：** 可以构建并自动审计“证据 A 单独不足、B 单独不足、A+B 才充分”的时序 QA 诊断任务。它还能明确区分无关、冗余和错误时段证据。这个性质是由反事实配对和数值规则验证的，不依赖模型表现。

**尚不支持：** “现有模型的错误主要来自互补检索，因此需要训练新的动态检索器”。在本任务中，联合材料已经直接给到模型；固定数值规则能解；模型却在事件阅读、充分性判断和精确时间差计算上都可能失败。若此时训练一个检索器，即使最终分数提高，也无法证明它解决的是互补检索。

**当前最合理的后续门槛：** 先把这一受控性质移植到更真实的跨变量数据，仍保持“相同单证据对应不同答案”的反事实证书；然后与简单事件检测＋时间匹配、传统多变量时间关联、以及现有集合/动态证据方法比较。只有在事件识别和简单时间匹配已够用、完整 A+B 也能由回答器稳定理解、而现有选择器仍找不到正确组合时，才有理由讨论新的条件证据价值模型。

## 6. 已有文献意味着什么？

本轮没有把“互补证据”当作空白概念。SetR 已研究让检索结果共同满足问题的信息需求；ARTIST 已研究逐步选择时序片段并决定何时停止；TSHarness 已有“证据不足时再感知”的流程；GRAIL 已研究根据已有证据寻找缺口。这些工作使“选集合”“继续检索”“判断何时停止”本身不能成为我们的创新。

本轮的潜在价值更窄：提供一个能形式化验证单证据不可判定性的跨变量时序测试协议，并把 **检索遗漏、充分性误判、数值感知和最终关系回答** 分开测量。我们尚未找到这些文献直接使用“同一显示证据在反事实世界中对应相反答案”的时序充分性测试，但这不是“尚未找到即等于不存在”的结论。投稿前仍需系统扩展查新，并复现或公平比较适用方法。

- [SetR: *Shifting from Ranking to Set Selection for Retrieval Augmented Generation*](https://aclanthology.org/2025.acl-long.861/)
- [ARTIST: *Adaptive Time Series Reasoning via Segment Selection*](https://zitniklab.hms.harvard.edu/ARTIST/)
- [TSHarness: *Zero-Shot Time-Series Question Answering via Decoupled Perception and Reasoning*](https://arxiv.org/abs/2610.04942)
- [GRAIL: *Subtraction Gets You More: Gap-Aware Retrieval for Multimodal Multi-Hop QA*](https://arxiv.org/abs/2605.28641)
